Le 4 novembre, OpenAI a annoncé l'acquisition de **Pierre Computer Company, Inc.**, la société derrière **Code Storage** (`code.storage`) et plusieurs outils open source pour développeurs. Montant non communiqué. Soumise aux autorisations réglementaires, l'opération laisse les deux entreprises indépendantes jusqu'à la clôture.

Rien d'anecdotique : si vous avez parcouru l'arborescence d'un projet ou relu un diff dans l'application Codex, vous avez utilisé du Pierre. **Trees** et **Diffs** y sont déjà embarqués. La même petite équipe a signé **Highlights**, un coloriseur syntaxique qui se met à jour pendant que l'agent streame du code, et l'API de Code Storage, qui stocke du code et en suit l'historique via Git.

## Le contexte : OpenAI a réécrit son propre Git la semaine dernière

Deux jours plus tôt, le 2 novembre, OpenAI publiait *Scaling Git at OpenAI*, le récit de **Pando**, son backend de contrôle de source maison. Latence médiane de push réduite de près de **80 %**, **~1 pétaoctet** de données Git servies par jour, **57 téraoctets** de packs en une seule heure dont plus de 99 % depuis le cache disque local.

La cause est nommée sans détour : Codex a changé l'échelle du développement interne. Plus de branches, plus de pushes concurrents, plus de clones depuis la CI et les environnements de dev. À un moment, la fiabilité du dépôt est passée **sous 90 %**, avec fetches lents et merges échoués.

La stratégie d'OpenAI tient en une phrase : faire de Codex « l'endroit où les développeurs et les agents mènent leurs projets les plus ambitieux », du premier branchement créé par un agent au déploiement.

## Pourquoi c'est important : la bataille se déplace du modèle vers le dépôt

Axios, qui a sorti l'information, lit l'opération comme une **attaque frontale contre GitHub**, propriété de Microsoft — actionnaire d'environ un quart d'OpenAI. Le reproche adressé à GitHub est connu : la plateforme a été conçue pour des humains alors qu'une part croissante du code est écrite par des agents — et elle a enchaîné les incidents de fiabilité à mesure que le code généré explosait.

Le marché bouge : Cursor a lancé **Origin** en août, et l'ex-CEO de GitHub, Thomas Dohmke, a annoncé son propre produit le mois dernier. OpenAI ne vend plus seulement l'écriture de code : il veut contrôler **l'infrastructure où ce code est stocké, relu et livré**.

## Ce que ça change pour nous, devs

**1. Git reste Git — pour l'instant.** Pando reste compatible avec le protocole et le client Git, et OpenAI contribue des correctifs en amont (packs téléchargés en parallèle, *explicit haves*). La couche basse reste un standard, pas un format propriétaire.

**2. Le dépôt devient une surface produit.** Navigation, diff, revue, stockage : ce sont exactement les primitives que Codex veut posséder. Si vos workflows s'appuient sur une API de forge (webhooks, checks, permissions), le fournisseur redevient un choix stratégique, pas seulement tarifaire.

**3. La revue de code est le prochain goulot.** Le mode *Edit* de Diffs corrige une ligne là où on repère le problème. Utile — mais cela déplace le risque vers la traçabilité : qui a écrit cette ligne, humain ou agent, avec quelle justification ? Commits signés, logs d'agent et attestations de build deviennent des briques de conformité.

**4. Open source, mais pas neutralité.** Les projets open source de Pierre resteront open source, et les clients de Code Storage pourront continuer à l'utiliser après la clôture pendant que les fonctionnalités migrent dans Codex. Une lib maintenue par un concurrent reste une lib dont la feuille de route se décide ailleurs.
