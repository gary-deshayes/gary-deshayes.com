Le **17 octobre 2026**, DeepSeek a publié **DeepSeek-V4.1-Flash-1017**, un nouveau checkpoint de son V4.1-Flash. Le modèle est live sur le site, l'app et l'API sous le nom `deepseek-flash`, et les poids sont sur Hugging Face. La carte du modèle annonce un « minor update » — c'est la formulation de DeepSeek, pas la mienne : les scores, eux, bougent de 2 à 11 points sur les onze benchmarks rapportés.

C'est le post le plus commenté de la journée sur Hacker News (591 points, 526 commentaires selon le briefing de The Context), ce qui pour un simple checkpoint en dit long sur l'attente autour des modèles ouverts.

## Ce que dit la carte du modèle

Ce qui est vérifiable directement sur le dépôt :

- **763 milliards de paramètres**, contexte de **1 million de tokens**, sortie recommandée à **256K tokens minimum**.
- **Licence MIT** sur le dépôt et sur les poids.
- **Pas de chat template Jinja.** Le dossier `encoding/` contient une implémentation Python autonome avec cas de test (multi-tours, tool calling, mode raisonnement, images). Pour la prod, `deepseek-recipe` fournit des bibliothèques Rust avec bindings Python qui encodent les requêtes Messages / Chat Completions / Responses au format V4 et reparsent la sortie, streaming compris.
- Paramètres d'échantillonnage : `temperature` 1.0, `top_p` 1.0.

L'architecture, documentée dans le rapport technique et reprise par MarkTechPost : MoE multimodal de 40 couches, 552B de paramètres de backbone plus 196B de paramètres « Engram », 8B activés par token en prefill et 16B en decode. Le KV cache global tombe à **890 octets par token** grâce au FP4, et le cache persistant à environ un huitième de celui de V4-Flash via SWA Bounded Replay.

## Les chiffres, avec la réserve qui va avec

Tous les scores ci-dessous sont **les chiffres de DeepSeek**, pas une évaluation indépendante.

| Benchmark | 1017 | V4.1-Flash | Claude Opus 5 |
| --- | --- | --- | --- |
| DeepSWE v1.1 | 77,0 | 74,2 | 74,0 |
| Terminal-Bench 4.0 | 42,3 | 31,2 | 51,8 |
| Agents' Last Exam | 35,4 | 31,8 | 28,6 |
| HLE sans outils | 42,6 | 36,8 | 56,3 |

Le motif est net : DeepSeek gagne du terrain sur le **code agentique** (DeepSWE, ProgramBench, Automation-Bench) et reste loin derrière sur la connaissance brute sans outils — 42,6 contre 56,3 pour Opus 5 sur HLE. Autrement dit, un modèle taillé pour faire tourner des boucles d'outils, pas pour répondre à des questions de culture générale.

## Pourquoi c'est important

Parce que le prix d'entrée d'un agent de code compétent vient encore de baisser. Un modèle à 77 sur DeepSWE sous MIT, c'est un modèle que n'importe qui peut auto-héberger, fine-tuner ou faire tourner hors ligne, sans contrat d'API et sans clause de rétention. Pour une équipe qui hésite à envoyer son code source chez un fournisseur américain, la question de la conformité change de nature.

## Implications concrètes pour les devs

**Dimensionnez le KV cache, pas seulement les paramètres.** 890 octets par token sur 1M de contexte, c'est ce qui rend l'auto-hébergement envisageable. Vérifiez la consommation réelle sur votre harness avant de promettre du long contexte à vos utilisateurs.

**Testez votre harness avant de migrer.** DeepSeek recommande son propre harness (v0.2.1-rc.1 minimum) et cite CodeBuddy et WorkBuddy ; les scores Terminal-Bench ont été obtenus dans Claude Code, DeepSWE dans Mini-SWE-V2. Un score de benchmark est un score de harness autant que de modèle.
